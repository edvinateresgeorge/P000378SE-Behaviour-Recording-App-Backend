4. DATABASE COLLECTIONS
(verified from MongoDB Compass — behaviourbridgedb)
───────────────────────────────────────────────────────────────

Collection Name        Description
──────────────────────────────────────────────────────────────
users                  All user accounts (ADMIN and CLIENT roles)
clients                Child/client profiles with name, dob, notes
                       and linked parent userId
behaviour_records      Core behaviour log records including
                       behaviourNames, triggerNames, strategyNames,
                       replacementNames, location, context,
                       intensity, notes and timestamps
emotion_checkins       Emotion check-in records with emotion,
                       emotionLevel, feelings, bodySignalCategories,
                       bodySignals, notes and checkedAt timestamp
safety_plans           Safety plan per user with contacts,
                       warningSigns, calmingStrategies, safeSpaces,
                       crisisContacts, emergencyContacts,
                       whatHelps, crisisHelplines, notes
appointments           Appointment booking records with clientName,
                       practitionerName, title, description,
                       location, type (IN_PERSON/ONLINE),
                       appointmentDate, durationMinutes, status
                       (PENDING/CONFIRMED/CANCELLED/COMPLETED),
                       sessionNotes and timestamps
behaviour_types        Lookup: behaviour type options (seeded)
triggers               Lookup: trigger options (seeded)
settings               Lookup: location/setting options (seeded)
responses              Lookup: strategy/response options (seeded)
record_behaviours      Junction: behaviour record to behaviour type
record_triggers        Junction: behaviour record to trigger
record_settings        Junction: behaviour record to setting
record_responses       Junction: behaviour record to response

NOTE: tasks, routines and invoices collections are created
dynamically when first record is saved — not visible in
Compass until data is added.

12. STARTUP ORDER
───────────────────────────────────────────────────────────────

Always start services in this order:

  1. MongoDB
     → Open MongoDB Compass
     → Connect: mongodb://localhost:27017
     → Verify behaviourbridgedb exists

  2. Spring Boot Backend
     → Open IntelliJ IDEA
     → Run BehaviourBridgeTracksApplication.java
     → Wait for: "Tomcat started on port 8080"
     → Verify Swagger: localhost:8080/swagger-ui/index.html

  3. Flutter Mobile App
     → flutter run -d chrome (web)
     → flutter run (Android)

  4. Admin Web Portal
     → Follow admin portal README setup instructions

14. SECURITY NOTES
───────────────────────────────────────────────────────────────

  1. LOCAL development database only — no auth configured
  2. JWT secret key MUST be changed before any production use
  3. All passwords stored as BCrypt hashes
  4. CORS configured to allow all origins (*)
     — must be restricted to specific domains in production
  5. No real patient data should be stored in development
  6. Swagger UI is publicly accessible in development
     — must be restricted or disabled in production

15. CLOUD DEPLOYMENT (future recommendation)
───────────────────────────────────────────────────────────────

Recommended Database: MongoDB Atlas (Free Tier available)
  Website: https://www.mongodb.com/atlas

Cloud connection string format:
  mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/
  behaviourbridgedb?retryWrites=true&w=majority

Steps to migrate to cloud:
  1. Create MongoDB Atlas account
  2. Create free tier cluster
  3. Whitelist IP addresses
  4. Create database user with password
  5. Update application.properties with Atlas URI
  6. Update JWT secret to strong random key
  7. Restrict CORS to specific domains
  8. Disable Swagger in production
